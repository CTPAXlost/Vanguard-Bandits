VANGUARD BANDITS REMASTER 2.0.5 — ПОЛНАЯ ПРОВЕРКА ЗАГРУЗКИ МИССИЙ И CI-МАТРИЦА

Причина обновления
Версия 2.0.4 прошла импорт Godot, Python-валидацию, компиляцию 39 GDScript и загрузку миссий I–III, но нормальная загрузка миссии IV зависла в интерактивном диалоге. Предыдущий workflow завершался на первой ошибке и поэтому не показывал состояние оставшихся миссий и smoke-тестов.

Исправления
1. Общая защита от зависания MissionBootSmoke
- В базовом battle_prototype.gd добавлен единый неинтерактивный режим для VBR_SMOKE_MISSION.
- Только обычная матрица загрузки миссий автоматически пропускает ожидание кнопки диалога.
- Отдельные StorySmoke, Mission3Smoke, Mission4Smoke и другие тесты не используют VBR_SMOKE_MISSION и продолжают проверять реальные диалоги/ветки.

2. Миссия IV
- В campaign_battle_v08.gd добавлено явное завершение boot-probe миссии IV.
- Снимаются mission_four_intro_pending, action_in_progress и диалоговая фаза.
- После этого запускается первый управляемый ход и v20 применяет тестовое масштабирование уровней.
- Добавлен маркер MISSION4_BOOT_PROBE_UNLOCKED.

3. Миссии III и V
- Миссия III переведена на общий helper _is_mission_boot_probe(3), без отдельной дублирующей проверки окружения.
- Для миссии V добавлен явный маркер успешного завершения неинтерактивной загрузки.

4. Усиленный MissionBootSmoke
- Проверяются intro-флаги миссий IV–VI, action_in_progress и диалоговая фаза.
- Проверяется завершение runtime-test level scaling.
- Диагностика теперь печатает состояние boot-флагов миссий IV–VII и масштабирования.
- Перед завершением теста сцена очищается десять кадров для освобождения renderer RID/ObjectDB.

5. Полный Mission4Smoke
- Старый тест, который подтверждал миссию IV после одного кадра, заменён полноценным тестом.
- Автоматически прокручивается реальный вступительный диалог.
- Проверяются четыре управляемых героя, снятие блокировки, применение уровней, поля опыта, Eigol у Kamorge и реальное перемещение по клетке.

6. GitHub Actions больше не останавливается на первой миссии
- Boot-матрица запускает все 9 случаев: миссии I–V, обе ветки VI и обе ветки VII.
- Даже при нескольких сбоях она собирает полный список BOOT_MATRIX_FAILURES и падает только после проверки всех случаев.
- Runtime-матрица аналогично запускает все 13 smoke-сцен и выводит полный RUNTIME_MATRIX_FAILURES.
- continue-on-error не используется.

7. Версия
- project.godot: 2.0.5
- Windows file/product version: 2.0.5.0
- GitHub artifact: Vanguard-Bandits-Remaster-2.0.5-Windows

Проверка перед выдачей
- Python validator.
- Синтаксис всех JSON.
- Баланс скобок всех GDScript.
- Проверка всех res:// ссылок и PNG.
- Проверка bash-синтаксиса каждого run-блока workflow.
- Повторная проверка после упаковки и распаковки ZIP.

Ограничение локальной среды
В контейнере нет Godot 4.6.3 и Wine, поэтому реальная компиляция GDScript, runtime-smoke и Windows-export должны быть подтверждены свежим GitHub Actions. В отличие от прежнего workflow, следующий лог покажет сразу все проблемные миссии/тесты, а не только первую ошибку.
