# Vanguard Bandits Remaster 1.9.9

Закрытый фанатский прототип тактической RPG на Godot 4.6.3 для Windows.


## Главное в версии 1.9.9

Исправлена причина падения из `logs_82025695480.zip`. GitHub запускал цепочку боевых скриптов через `godot --script`. В этом специальном режиме проектные autoload-синглтоны не поднимаются как при обычном запуске сцены, поэтому корректные обращения к `CampaignState` ошибочно компилировались как `Identifier not found` во всех шести слоях боя.

- удалена ложная standalone-проверка `script_chain_smoke.gd`;
- вся цепочка боя проверяется через настоящий запуск `MissionBootSmoke.tscn`, где загружается обычный `BattlePrototype.tscn` с autoload-синглтонами;
- блокирующий boot-smoke запускает миссии I, II, обе ветки III, IV, V и обе стороны VI;
- для каждого запуска проверяются код возврата Godot, маркер завершения и ошибки компиляции/runtime;
- импорт Godot теперь сохраняется в лог и отдельно блокирует сборку при `SCRIPT ERROR`, `Parse Error`, `Invalid access`, `Failed to load script` или `Compilation failed`;
- Windows-export также сохраняет лог, проверяет код возврата и останавливает сборку при ошибках экспорта;
- `continue-on-error` не используется, обязательные runtime-smoke и Windows-export не отключены;
- сохранены исправления 1.9.6–1.9.8: совместимость домов миссии II, полный отряд главы VI, ИИ королевств, balance-профили и независимый финализатор вступления;
- локально пройдены 194 Python-регрессионных теста, проверены 36 JSON, 524 PNG, 355 статических `res://`-ссылок, YAML и shell-синтаксис обоих workflow.

## Главное в версии 1.9.7

Исправлена реальная ошибка из `logs_81876296079.zip`: обычный запуск главы VI создавал 23 боевых юнита, но массив управляемого отряда оставался пустым (`party=0`). Причина находилась в `campaign_battle_v19.gd`: собственная ветка `_spawn_mission_units()` обходила родительские сценарии миссий и после создания Bastion, Andrew, Zeira, Ione и Reyna не вызывала `_setup_player_party()`. Теперь все пять героев регистрируются в обычном жизненном цикле сцены до начала первого хода.

Дополнительно исправлены две скрытые ошибки главы VI:

- Logan, Claire, Shion, Alden, Devlin и Barlow раньше создавались функцией героя как управляемые союзники. Теперь лидеры королевств изначально принадлежат своим сторонам, управляются ИИ и только после выбора игрока переводятся в союзную или вражескую команду;
- добавлены отсутствовавшие balance-профили для восьми сочетаний персонажей и ATAC, поэтому миссия больше не должна запускаться на аварийных характеристиках.

Обычный smoke-тест требует ровно пять управляемых героев, а отдельный smoke главы VI проверяет обе стороны, состав отряда, ИИ королевских лидеров, шесть южных подкреплений и сохранение выбранного союза. Сообщения об отсутствующем balance-профиле теперь останавливают GitHub Actions.

## Главное в версии 1.9.6

Исправлена реальная ошибка GitHub Actions из лога `logs_81873053197.zip`: миссия II использует старый формат размеров домов `[ширина, глубина]` и отдельное поле `height`, а `_create_house()` ожидал три элемента `[ширина, высота, глубина]`. Это вызывало `Out of bounds get index '2'` в `battle_prototype.gd:350` и останавливало обязательный smoke-тест. Теперь загрузчик принимает оба формата и безопасно обрабатывает неполные данные.


## Главное в версии 1.9.5

### Критическое исправление загрузки боя

В сборке 1.9.4 родительская инициализация боевой сцены вызывалась только внутри условия шестой миссии. Поэтому главы I–V открывали сцену, но не создавали карту, интерфейс и отряды. В 1.9.5 вся цепочка наследуемых `_ready()` выполняется и ожидается для каждой миссии.

Smoke-тесты больше не достраивают поле приватными методами и не вызывают анимацию перемещения напрямую: проверяется только настоящий запуск `BattlePrototype.tscn`, обычный ввод и обычный жизненный цикл Godot. Ошибки импорта, runtime-smoke и Windows-export остаются блокирующими.

### Глава V

- проходы замка полностью открыты: без створок, столбов, перемычек, центральных блоков и скрытых непроходимых клеток;
- Sadira, Franco и Halak находятся на открытом поле и доступны для атаки обеим сторонам;
- магазин показывает весь каталог, изображения, цены и количество предметов;
- Faulkner сохраняет полный набор атак, включая «Град огня с неба» за 60 энергии;
- Zakov атакует союзника только при настоящем эффекте дезориентации, а лечение выбирает только союзные цели.

### Глава VI — «Война Севера и Юга»

Глава доступна только в ветке, где Kamorge погиб. После встречи с Zeira, Ione и Reyna игрок выбирает Южное или Северное королевство. Выбранная сторона становится союзной, другая армия сражается и с ней, и с отрядом Bastion. Решение записывается в сохранение.

**Южное королевство:** Logan / Crimson, Claire / Rahabor, Shion / Rahabor, шесть Nordilian / Rahabor и подкрепление ещё из шести Rahabor после гибели первой группы.

**Северное королевство:** Alden / Altagrave, Devlin / Snow Soldier, Barlow / Ratatosk и шесть Matisse / Ratatosk.

Реализованы два действия Logan, два усиления урона на 100%, отражение, магическая неуязвимость и «Айсберг» Alden, его восстановление союзников в собственный ход, клон и неотражаемое комбо Devlin.

## Управление

- ЛКМ — выбрать ATAC, клетку или цель;
- стрелки — выбрать направление после перемещения;
- Enter — подтвердить цель;
- Esc — отменить выбор;
- «Отменить перемещение» — вернуть юнит до выполнения действия;
- WASD — камера;
- Q/E — вращение;
- колесо — масштаб;
- F — фокус на выбранном ATAC;
- F9 — безопасный режим 30 FPS;
- F10 — диагностика производительности.

## Сборка Windows через GitHub

1. Полностью замените содержимое закрытого репозитория файлами из архива.
2. Обязательно загрузите скрытую папку `.github`.
3. Откройте `Actions → Build Windows Remaster`.
4. Нажмите `Run workflow`.
5. После успешных проверок скачайте артефакт `Vanguard-Bandits-Remaster-Windows-x64`.

GitHub Actions импортирует проект в Godot, запускает runtime-проверки прежних миссий и обеих сторон главы VI, затем экспортирует Windows x64. Если новая глава или одна из её армий не создаётся, экспорт останавливается и прикладывает диагностический лог.
