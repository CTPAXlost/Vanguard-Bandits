Vanguard Bandits Remaster 1.9.18
ОПТИМИЗАЦИЯ GITHUB ACTIONS И КЕШИРОВАНИЕ GODOT

Причина 35-минутной сборки 1.9.17:
- GitHub Actions каждый запуск заново скачивал полный пакет export_templates.tpz размером около 1,2 ГБ.
- Скорость официального зеркала в присланном логе была около 580 КБ/с.
- У всего задания стоял timeout-minutes: 35, поэтому загрузка прерывалась на 92%, а Godot import, runtime-smoke и Windows-export даже не запускались.

Что исправлено:
1. CI разделён на два задания:
   - Validate and runtime smoke — Python, импорт, компиляция GDScript и все runtime-smoke.
   - Windows export — запускается только после успешных тестов.
2. Godot 4.6.3 кешируется через actions/cache/restore и actions/cache/save.
3. Импортированная папка .godot кешируется по хешу исходников, сцен, данных и изображений.
4. Export templates кешируются отдельно.
5. Из полного TPZ извлекаются и сохраняются только два необходимых Windows x86_64 шаблона:
   - windows_release_x86_64.exe
   - windows_debug_x86_64.exe
6. Основной источник скачивания — GitHub Releases Godot; медленное официальное зеркало оставлено только резервным.
7. Первой загрузке шаблонов разрешено до 70 минут, всему export-заданию — до 120 минут. После создания кеша повторные сборки не должны повторно скачивать 1,2 ГБ.
8. Кеш шаблонов сохраняется сразу после установки, до Windows-export.
9. Upload artifact использует compression-level: 0, чтобы не тратить время на повторное сжатие готовой Windows-сборки.
10. Все тесты остаются блокирующими. continue-on-error отсутствует.

Ожидаемое поведение:
- Первый запуск после обновления может занять дольше обычного, поскольку GitHub должен один раз получить export templates.
- После успешного сохранения кешей следующие сборки должны вернуться к нескольким минутам, если кеш не был удалён или вытеснен GitHub.
